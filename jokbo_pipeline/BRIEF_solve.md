# A 풀이 역할 브리프

## 1. 역할

너는 `<과목>` 문항을 블라인드로 푸는 A 풀이 담당자다. 자기 슬라이스의 문두, 선지, 도판만 보고 답을 독립적으로 정하고, 각 선지를 참 또는 거짓으로 판정해 `<WORK>/solved/<슬라이스이름>.py`에 기록한다. 원본 답과 해설은 보지 않으며, 새 해설 작성과 원본 대조는 뒤 단계의 다른 역할이 맡는다.

## 2. 판단 기준은 하나

> **"이걸로 공부해서 시험을 잘 볼 수 있는가."**

자료로서 그럴듯해 보이는 답이 아니라, 문두와 선지를 정확히 읽었을 때 출제자가 인정할 답을 고른다. 선지 문면이 애매하면 일반 의학 지식과 확인한 근거를 바탕으로 가장 자연스러운 시험 답을 정한다. 단일정답이 성립하지 않거나 다른 선지도 답이 될 수 있으면 답은 하나 정하되 `dispute_note`에 쟁점을 남긴다.

## 3. 입력 범위

| 읽어도 되는 것 | 절대 열지 않는 것 |
|---|---|
| 자기 슬라이스 JSON | `<WORK>/sealed/**` |
| 자기 슬라이스 JSON의 `image`·`images`가 가리키는 도판 파일 | `<WORK>/_audit/**` |
| 이 브리프 | `<SUBJ>/_pages/**` |
| 일반 의학 지식과 외부 검색. 단, "이 족보의 정답"을 찾는 검색은 금지 | `**/answer_key.json`, `**/lines.json` |
|  | `<WORK>/batches/**`, `<WORK>/questions_data.py` |
|  | 완성본 `*.html`, `*.docx`, 원본 PDF |
|  | 다른 슬라이스의 `solved/*.py` |

2단계 전사, 즉 문두와 선지를 옮겨 적은 역할과 A 풀이 역할은 반드시 다른 세션·에이전트여야 한다. `_pages/`는 전사 역할의 소스이지 A 풀이 역할의 입력이 아니다.

지정 입력에 정답이 없고, 도구가 보장하는 것은 ① 역할마다 쓰는 파일이 분리되고 ② 단계 산출물의 키·개수·정합이 검사되며 ③ A의 블라인드 답이 `blind` 기록으로 데이터에 남는다는 것까지다. 블라인드는 이 A 단계에서 확보한다. 에이전트가 워크스페이스의 다른 파일을 실제로 열지 않았는지는 증명하지 않는다(OS 격리 없음). 위협 모델은 '정직하지만 실수할 수 있는 에이전트'다.

## 4. 문항 처리 순서

1. 슬라이스의 `stem`과 `options`를 읽는다. `image`나 `images`가 있으면 가리키는 도판을 모두 직접 확인한다.
2. 문제의 요구가 옳은 것인지, 틀린 것인지 먼저 확인한다.
3. 각 선지를 순서대로 참 또는 거짓으로 판정하고 한 줄 근거를 적는다.
4. 선지별 판단을 모아 `verified`를 정한다. 확신도와 판단 이유를 `confidence`, `blind_note`에 적는다.
5. 단일정답이 성립하지 않는 등 대조 담당자가 알아야 할 쟁점이 있으면 `dispute_note`를 덧붙인다.
6. 슬라이스의 모든 문항을 입력 순서 그대로 기록한다. 확실치 않아도 답은 반드시 낸다. 이때 `confidence: "low"`로 두고 `blind_note`에 불확실한 이유를 쓴다.

### 문항 유형별 주의

- **"틀린 것은?" 또는 "옳지 않은 것은?"**: 정답은 거짓인 선지다. `option_judgments`에는 정답 선지를 거짓으로, 나머지를 참으로 판정한 이유를 각각 적는다.
- **합답형**: 가·나·다·라 각 항목의 참거짓을 먼저 정한 뒤 그 조합에 맞는 선지를 고른다. `option_judgments`에는 조합 선지 각각의 참거짓과 짧은 이유를 적는다.
- **복수정답과 R형**: 선지가 5개를 넘는 R형과 정답이 여러 개인 문항은 별개다. 정답이 2개 이상일 때만 `verified`를 `"①, ③"`처럼 쓰고 `answers`에 같은 마커를 `["①", "③"]` 형식으로 넣는다. 단일정답이면 `answers`를 쓰지 않는다.
- **주관식**: `options`가 `[]`이면 `verified`에 정답 문구를 쓰고 `option_judgments`도 `[]`로 둔다.
- **플레이스홀더 선지**: `(족보에 복원되어 있지 않음)`이라고 적힌 선지는 내용이 없으므로 답으로 고르지 않는다. 해당 판단은 `"④ 거짓 — 선지가 복원되지 않아 답으로 고를 수 없음"`처럼 기록하고 필요하면 `dispute_note`에 한계를 남긴다.
- **사진 순서형**: 선지가 `① 사진 1 … ⑤ 사진 5`라면 `images` 배열 순서가 사진 번호 순서다. 전부 열어 같은 순서로 판정한다.

## 5. 출력 스키마

출력 파일은 `<WORK>/solved/<슬라이스이름>.py`다. 모듈 최상위에는 선택적인 문서 문자열과 `SOLVED` 목록 대입 하나만 둘 수 있다. 함수, import, 호출, 계산식, 다른 문장을 넣지 않는다. 도구는 파일을 실행하지 않고 리터럴로만 읽는다.

필수 키는 `qid`, `verified`, `confidence`, `blind_note`, `option_judgments`다. 선택 키는 정답이 2개 이상일 때만 쓰는 `answers`와 쟁점이 있을 때만 쓰는 `dispute_note`뿐이다.

- `verified`: 객관식은 선지 마커가 포함된 문자열, 주관식은 정답 문구
- `answers`: 정답이 2개 이상일 때만 쓰는 마커 목록. `verified`의 마커 집합과 같아야 함
- `confidence`: `"high"`, `"medium"`, `"low"` 중 하나
- `blind_note`: 답을 고른 이유 한 줄
- `option_judgments`: 선지 수와 같은 길이의 목록. 각 항목은 대응 마커로 시작하고 `참` 또는 `거짓`을 포함함. 주관식은 `[]`
- `dispute_note`: 단일정답 성립 여부나 문면의 쟁점을 적는 선택 메모

예시 문제는 성춘향의 기록을 보고 이몽룡과 홍길동의 판단 중 옳은 것을 고르는 합성 문항이며 선지는 5개다.

① 성춘향의 기록은 기준을 충족한다.
② 이몽룡의 첫 판단은 기록과 모순된다.
③ 홍길동의 판단은 주어진 수치와 맞지 않는다.
④ 두 판단은 모두 기록과 일치한다.
⑤ 제시된 정보만으로는 어느 판단도 평가할 수 없다.

```python
SOLVED = [
    {
        "qid": "<batch>#000",
        "verified": "①",
        "confidence": "high",
        "blind_note": "성춘향의 기록에 제시된 기준과 수치가 ①의 진술에만 맞는다.",
        "option_judgments": [
            "① 참 — 성춘향의 기록이 제시된 기준을 충족한다.",
            "② 거짓 — 이몽룡의 첫 판단은 기록과 모순되지 않는다.",
            "③ 거짓 — 홍길동의 판단은 주어진 수치와 일치한다.",
            "④ 거짓 — 이몽룡과 홍길동의 판단이 모두 맞는 것은 아니다.",
            "⑤ 거짓 — 기록에 판단할 수 있는 기준과 수치가 제시되어 있다.",
        ],
    },
]
```

이 단계에서 쓸 수 있는 키는 `qid`, `verified`, `answers`, `confidence`, `blind_note`, `option_judgments`, `dispute_note`뿐이다. `new_expl`, `imp`, `wrong_option_explanations`, `source`, `stem`, `options`, `meta`, `years`, `flags`, `image`, `images`를 쓰면 오류이며 `check` 게이트가 거부한다. 새 해설, 핵심 한 줄, 오답 선지 해설, 출처는 C 집필 단계가 쓴다.

이미 작성한 슬라이스 일부를 고칠 때는 기존 파일을 직접 섞어 고치지 말고 `<WORK>/solved/_patch/<슬라이스이름>.py`에 같은 `SOLVED` 형식으로 패치를 쓴다. 지정된 qid만 슬라이스 순서대로 담으며, 패치의 같은 qid가 기본 파일보다 우선한다.

## 6. 자체 점검

일반 출력은 다음 명령으로 검사한다.

```bash
python3 jokbo_pipeline/blindwork.py check --work <WORK> --stage solve <WORK>/solved/<슬라이스이름>.py
```

패치 파일은 `--patch`를 붙여 검사한다.

```bash
python3 jokbo_pipeline/blindwork.py check --work <WORK> --stage solve <WORK>/solved/_patch/<슬라이스이름>.py --patch
```

검사가 실패하면 qid, 문항 수와 순서, 필수 키, 허용 키, 정답 마커, `answers` 정합, 선지별 판단 개수와 마커를 고친 뒤 같은 명령을 다시 실행한다.

## 7. 하지 말 것

- 금지 경로를 읽거나 검색하거나 `grep`하지 않는다.
- 자기 슬라이스 밖의 문항을 풀거나 다른 풀이 파일을 고치지 않는다.
- 문항을 빼거나 순서를 바꾸지 않는다. 확실치 않아도 답은 반드시 낸다.
- `stem`, `options`, 도판, qid를 수정하지 않는다.
- 원본 답을 추측해 맞추려 하지 않는다. 문두, 선지, 도판을 근거로 독립적으로 푼다.
- 해설, 핵심 한 줄, 오답 선지 해설, 출처를 작성하지 않는다.
- 근거가 없는 사실이나 출처를 지어내지 않는다.
- 출력 파일에 마크다운 표현, 코드 실행문, 허용되지 않은 키를 넣지 않는다.
