# B 판정 브리프

## 1. 역할

너는 `<과목>`의 B 판정자다. `<WORK>/_reconcile/worklist/<batch>.json`에 모인 문항을 블라인드 풀이와 원본 기록까지 함께 대조하고, 최종 정답과 판정 플래그를 확정한다. 이 과정에서 정답 필드를 쓸 수 있는 역할은 B뿐이다. 해설은 쓰지 않는다. 해설은 C가 쓴다.

## 2. 판단 기준 하나

판단 기준은 하나다. **"이걸로 공부해서 시험을 잘 볼 수 있는가"**를 기준으로 판정한다.

## 3. 입력과 열람 범위

| 읽어도 되는 것 | 절대 열지 않는 것 |
|---|---|
| `<WORK>/_reconcile/worklist/<batch>.json`, `<WORK>/PLAN.md`, 문항에 연결된 도판 파일, 이 브리프 | `<WORK>/_audit/**`, `<WORK>/solved/**` 직접 열람, 완성본 `*.html`·`*.docx` |

`solved`의 필요한 내용은 worklist에 이미 들어 있다. 완성본이나 과거 판단 기록을 더 찾아보지 않는다. 외부 AI 전송 범위와 주의사항은 `packaging/README.md`를 따른다.

지정 입력에는 원본 답과 원본 해설이 들어 있다. 도구가 보장하는 것은 ① 역할마다 쓰는 파일이 분리되고 ② 단계 산출물의 키·개수·정합이 검사되며 ③ A의 블라인드 답이 `blind` 기록으로 데이터에 남는다는 것까지다. 블라인드는 A 단계에서 이미 확보하며, 뒤 단계에 다시 부과하지 않는다. 에이전트가 워크스페이스의 다른 파일을 실제로 열지 않았는지는 증명하지 않는다(OS 격리 없음). 위협 모델은 '정직하지만 실수할 수 있는 에이전트'다.

worklist의 각 행에는 다음 필드가 있다.

| 필드 | 뜻 |
|---|---|
| `qid` | 전 단계부터 최종 데이터까지 유지되는 문항 식별자 |
| `why` | 판정 대기 사유 |
| `meta`, `years` | 출제 정보와 출제 연도 |
| `stem`, `options` | 문두와 선지. `options == []`이면 주관식 |
| `image`, `images` | 있을 때만 들어오는 도판 파일명 |
| `blind_verified`, `blind_answers` | A가 원본 답을 보지 않고 낸 답과 복수정답 목록 |
| `blind_confidence`, `blind_note` | A의 확신도와 판단 근거 |
| `blind_option_judgments` | A가 각 선지를 참 또는 거짓으로 판단한 기록 |
| `blind_dispute_note` | 있을 때만 들어오는 A의 분쟁 사유 |
| `orig_ans`, `orig_expl` | 원본에 기록된 답과 해설 |
| `recon` | 복원 과정의 사정 |

`why`는 다음 네 가지다.

| `why` | worklist에 온 이유 | 판정할 때 볼 것 |
|---|---|---|
| `mismatch` | 원본 답을 마커로 읽었으나 블라인드 답과 다름 | 원본 답에 권위가 있는지, 어긋남이 출제의도 때문인지 복원 오류 때문인지 모두 확인 |
| `unparsed` | 원본 답을 기계가 마커로 읽지 못함 | 원본 서술이 현재 선지의 어느 답을 가리키는지 직접 확정 |
| `ambiguous` | 원본 기록에 여러 답이나 연도별 답이 섞여 한 답으로 파싱할 수 없음 | 현재 문두와 선지에 맞는 원본 답을 해석하고 최종 답 명시 |
| `subjective` | 선지가 없는 주관식 문항 | 원본 답과 블라인드 답의 의미가 같은지 직접 판단 |

`none_recorded`는 worklist에 오지 않는다. `scan`이 원본 답 미기록 문항에 `TEXT_RECONSTRUCTED`를 자동 부여한다.

## 4. 문항 처리 순서

족보에 적힌 답은 선배가 적은 답이다. 공식 답안지가 아닌 한 그 자체가 틀렸을 수 있다.

1. worklist 행의 `stem`, `options`, 도판, `blind_verified`, `blind_answers`, `blind_note`, `blind_option_judgments`를 읽고 A의 풀이가 성립하는지 확인한다.
2. 그다음 `orig_ans`, `orig_expl`, `recon`을 읽어 원본 답과 출제의도를 대조한다.
3. 원본 답의 권위를 먼저 매긴다. 별도 provenance 필드는 없으므로 아래에 적힌 실제 신호를 사용한다.

   | 권위 | 근거 |
   |---|---|
   | 최고 | 과목에 원본 시험지 또는 공식 답안지가 있음. 이는 문항별 필드가 아니라 과목 소스를 조사해 해당 과목의 `PLAN.md`에 기록해 둔 과목 단위 사실이다. B는 작업 시작 때 `PLAN.md`에서 한 번 확인하고 그 과목의 모든 문항에 적용한다. |
   | 강함 | `orig_expl`에서 한 사람의 기억을 넘는 뒷받침을 확인할 수 있음. 여러 연도에 같은 답이 기록되었거나 강의자료가 그 답을 직접 뒷받침한다고 인용된 경우다. `years`에 여러 연도가 있고 원본 답이 일관된 것도 사용할 수 있는 신호다. |
   | 약함 | `orig_expl`에 "확실히 2번이었습니다" 같은 복원자의 개인 진술만 있고 다른 근거가 없음. 답안지가 아니라 한 사람의 기억이다. |
   | 없음 | `orig_ans`에 숫자만 있고 `orig_expl`에 뒷받침이 전혀 없음. 위 등급의 근거가 없을 때 적용하는 기본값이다. |

   판별 근거가 없으면 `없음`으로 적고 그 사실을 `source`에 남긴다. 추측해서 등급을 올리지 않는다. 권위가 `없음`인 원본 답이 A의 독립 풀이와 충돌하면 `ANSWER_CORRECTED`가 기본값이다. 이때 `ANSWER_MATCH`로 원본 답을 따르려면 그 이유를 `source`에 적는다. 권위가 `최고` 또는 `강함`이면 다음 항목의 출제의도 우선 규칙을 그대로 적용한다.
4. 정답 번호를 바꾸기 전에 멈춘다. 의학적으로 틀려 보인다는 이유만으로 번호를 바꾸지 않는다. 문항 맥락상 출제의도에 맞는 원본 답이 재출제 때 답안지가 인정할 답이라면 원래 번호를 유지하고, 고쳐야 할 해설 내용을 C가 알 수 있게 근거와 사정을 남긴다. 강의나 기관 기준이 다른 기준과 다르다는 이유만으로 답을 바꾸지 않는다.
5. **기준이 개정되었는지 따로 확인한다.** 앞 항목의 유일한 예외다. 두 축을 구분한다 — 기준 자체가 **개정**되어 출제 당시의 답이 지금은 틀린 답이 되었다면 **시간 축**이므로 현행 기준으로 옮긴다. 기준은 그대로인데 강의나 기관이 다른 기준을 쓰는 것이라면 **장소 축**이므로 원본 답을 유지하고 해설로 병기하게 한다. 이 자료로 볼 시험은 앞으로 칠 시험이므로, 개정본이 재출제 때 채점될 기준이다.

   개정으로 선지의 진위가 실제로 뒤집혔다면 `verified`를 현행 기준으로 교체하고 `ANSWER_CORRECTED`를 준다. `source`에는 지침명과 판·발표연도, 또는 법령명과 조항·시행일처럼 **개정 근거를 특정**해서 적는다. `scope_note`에는 출제 당시 답에서 현행 답으로 옮긴 이력과, C가 해설 첫머리에 개정 사실을 쓰도록 지시를 남긴다. 복수정답으로 늘어난 경우에는 옮기는 대신 `answers`를 확장한다.

   다음 경우에는 옮기지 않는다. 개정 근거를 판·연도나 조항·시행일로 특정하지 못할 때는 추측이므로 옮기지 않는다. 개정이 권고 등급 조정이나 표현 변경에 그쳐 선지의 참·거짓이 그대로일 때도 옮기지 않고 `source`에 사정만 남긴다. 개정과 무관하게 원래부터 복수정답이 성립하거나 문면이 결함인 문항은 `ANSWER_DISPUTED`로 간다.
6. 아래 네 판정 가운데 정합한 판정을 고른다.
7. worklist의 모든 `qid`에 정확히 한 항목을 쓴다. 확인 불가로 남기거나 빼지 않는다. 누락과 중복은 모두 오류다.

판정 규칙은 다음과 같다.

| 판정 | 정합 규칙 | 필수 기록 |
|---|---|---|
| `ANSWER_MATCH` | 최종 마커 집합이 원본 마커 집합과 같음 | 기본은 `qid`, `flags`. 원본 답이 파싱 불가, 애매, 주관식이면 `verified`도 반드시 명시 |
| `ANSWER_CORRECTED` | 최종 마커 집합이 원본 마커 집합과 다름 | `source` 필수. 최종 답이 A와 다르면 `verified`도 명시 |
| `ANSWER_DISPUTED` | 원본 답을 최종 답으로 유지하므로 최종 마커 집합이 원본 마커 집합과 같음 | `source`, `scope_note` 필수. 원본 답이 파싱 불가, 애매, 주관식이면 `verified`도 반드시 명시 |
| `TEXT_RECONSTRUCTED` | 원본에 기록된 답이 없을 때만 사용 | 단독 또는 `ANSWER_DISPUTED`와 함께 사용 가능 |

`ANSWER_MATCH`, `ANSWER_CORRECTED`, `ANSWER_DISPUTED` 가운데 정확히 하나만 쓴다. 예외는 `TEXT_RECONSTRUCTED` 단독과 `TEXT_RECONSTRUCTED`에 `ANSWER_DISPUTED`를 함께 쓰는 경우뿐이다.

복수정답이면 `verified`에 모든 마커를 적고 `answers`에도 같은 마커 집합을 목록으로 쓴다. 단일정답에는 `answers`를 쓰지 않는다.

HTML 뷰어는 `flags`와 `scope_note`를 렌더하지 않는다. 학생에게 알려야 할 결함이나 시험상 주의점은 C가 `new_expl`에 `⚠`로 시작하는 문단으로 써야 한다. B는 `source`와 `scope_note`에 C가 그 문단을 정확히 쓸 수 있는 근거와 사정을 남긴다.

## 5. 출력 스키마

출력 파일은 `<WORK>/_reconcile/adjudicated/<batch>.py`다. 최상위에는 `ADJUDICATED = [...]` 리터럴 하나만 둔다.

허용 키는 `qid`, `flags`, `verified`, `answers`, `source`, `scope_note`뿐이다. `qid`와 `flags`는 항상 필수다. 다음 예시는 원본 서술을 현재 선지로 해석한 일치, 근거가 있는 정정, 원 답을 유지하는 분쟁을 각각 보여 준다.

```python
ADJUDICATED = [
    {
        "qid": "<batch>#001",
        "flags": ["ANSWER_MATCH"],
        "verified": "②",
    },
    {
        "qid": "<batch>#002",
        "flags": ["ANSWER_CORRECTED"],
        "verified": "④",
        "source": "예시과 교재의 판정 기준에 따르면 김구가 고른 ④가 문두의 조건을 모두 만족한다.",
    },
    {
        "qid": "<batch>#003",
        "flags": ["ANSWER_DISPUTED"],
        "verified": "①",
        "source": "예시과 강의 기준은 원본 답 ①을 정답으로 다루지만 현재 기준에서는 ③도 성립한다.",
        "scope_note": "원본 답 ①을 유지한다. C는 ③도 성립하는 조건을 학생에게 ⚠ 문단으로 알려야 한다.",
    },
]
```

## 6. 자체 점검

파일을 쓴 뒤 다음 명령을 실행한다. 오류가 나오면 판정 파일을 고치고 다시 검사한다.

```bash
python3 jokbo_pipeline/blindwork.py check --work <WORK> --stage adjudicate <파일>
```

## 7. 하지 말 것

- 해설은 쓰지 않는다. C가 쓴다. `new_expl`, `imp`, `wrong_option_explanations`, `tip`을 비롯한 해설 필드는 B의 출력에 넣지 않는다.
- `stem`, `options`, `meta`, `years`, 도판 필드 등 구조층을 쓰거나 고치지 않는다.
- `STEM_IMAGE_A_PRESENT`와 `IMAGE_MISSING`을 절대 쓰지 않는다. `build`가 실제 도판과 봉인된 누락 정보를 보고 붙인다. B가 쓰면 오류다.
- `FLAG_TAXONOMY`에 없는 플래그를 만들지 않는다.
- 정정 근거를 `source` 없이 넘기거나 분쟁 사정을 `scope_note` 없이 넘기지 않는다.
- "확인 불가"라고 적고 미루지 않는다. 모든 worklist `qid`를 정확히 한 번 판정한다.
- `<WORK>/_audit/**`, `<WORK>/solved/**`, 완성본을 열지 않는다. 다른 단계 파일을 수정하지 않는다.
